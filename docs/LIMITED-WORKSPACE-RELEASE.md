# Limited unverified workspace access

The owner explicitly approved this scope after the initial authentication release: signed-in unverified users may view their own dashboard, edit their academic profile, manage professors, and upload/read/delete their private documents. Mailbox operations, sending and campaign approvals remain verification-gated. This supersedes the pending-access blocker described in AUTH-FOLLOWUP-RELEASE.md.

The API uses an explicit path/method allowlist. All other routes still require verified or preserved legacy access. Approved professor management includes create/import, edit, archive/restore/delete and local source-confirmation metadata. Email-draft spreadsheet import, AI drafts, messages, approvals, retries, follow-ups, mailbox consent/read/check/sync/disconnect, outreach controls and opt-out mutations remain blocked for limited users. Existing account-security and recovery routes retain their previous policy.

The limited dashboard queries only the authenticated user's profile, professor list, private documents and account. Mailbox identities, message history, approval snapshots, delivery details, configured test recipients and live controls are omitted. The UI labels the account **Email Not Verified**, provides the permitted workspace controls, and hides or disables unavailable outreach/mailbox controls. Professor-only import remains available even when an uploaded spreadsheet includes email-draft columns; those columns create no drafts.

Every existing owner check and document quota remains. Limited workspace mutations additionally share per-user (60/hour), per-IP (120/hour), and global (1000/hour) limits. This does not change verified/legacy account quotas. Email verification fields are never set by workspace access. Pending accounts can use the new scope without re-registration or transactional email delivery.

Tests cover authentication, the approved CRUD routes, user-data isolation, owner-only document reads/deletes before storage access, blocked sensitive operations, redacted dashboard state, exact method/path matching, rate limits, and preserved verified/legacy behavior. A local browser flow performs mail-free signup/login, checks the unverified label and restricted controls, imports professors, uploads documents, and exercises passkey/recovery options using an isolated database and virtual authenticator. No real emails are sent.

Validation before release: 251 automated tests passed in 15 files. Both TypeScript checks and the production frontend build passed. Full npm audit reported zero vulnerabilities. Native Workers checks passed for Gmail and WebAuthn/Turnstile using synthetic/intercepted network traffic. The isolated browser signup-to-workspace and passkey/recovery flow passed with no JavaScript errors or deliveries. Stable production-data and current-setting fingerprints matched before release.
