# Campaign reuse, draft deletion, attachment consent and upcoming revisions

Deployed to https://ms-professor-agent-malang43.vercel.app/ on November 6, 2026. Worker version: `84fc2810-7e93-496f-9e67-3ae2be2b5d0d`. Vercel deployment: `dpl_FL62EidqbJDRZoGHT7qdxhpu7MZ1`.

1. **Cause of cancelled-recipient exclusion:** Smart Import retained its browser-session submission identity after successful import. The API correctly recovered the original messages for that identity, and review excluded their cancelled statuses. This was import retry recovery being mistaken for new campaign creation.
2. **New campaign reuse:** A retired cancelled or deleted import now causes an explicit new Add to Campaign action to reserve a fresh import identity before submitting. New message IDs and approvals are independent. Unapproved draft retries retain their existing identity. Deleted-import reuse is covered by API tests; cancelled reuse is also covered end to end in the browser using identical spreadsheet content.
3. **Old cancellations:** Existing cancelled messages and jobs are never revived. New revision guards reject cancelled campaigns and cancelled steps. Browser tests verify old IDs remain cancelled.
4. **Duplicate warnings:** Confirmed contact, unconfirmed submission, pending outreach and cancelled unsent outreach remain distinct. Cancelled unsent contact history is informational, without falsely claiming delivery. Repeat approval requires explicit acknowledgment of fresh history; the new campaign ID and decision are retained. Suppressions and opt-outs remain enforced.
5. **Delete Draft:** Owner-scoped confirmation deletes only a single eligible unapproved import group, its selected draft rows and draft associations. Shared/reusable documents remain in Documents. Any approval, transport, active job or inconsistent state blocks the entire mutation. Other campaigns and users are preserved.
6. **Forgotten CV:** Select Campaign actions > Edit Upcoming Emails, select eligible messages, choose the CV, review old and new values and explicitly approve. Only those selected future unsent messages receive the approved attachment overlay.
7. **Scheduled editing:** Eligible initial emails and sequence follow-ups support subject, body, attachment selection/removal and future date changes. Opening or previewing edits does not write database records. Stale, due, claimed, attempted, uncertain, sent, replied, cancelled and suppressed targets are rejected. Whole-sequence validation prevents fixed follow-ups preceding their prerequisites or becoming an immediate backlog after rescheduling.
8. **Sent-message immutability:** Original message content, schedules, transport snapshots, authorizations and sending receipts are not overwritten. State presentation exposes the effective approved revision while retaining original values. Sent targets become read-only.
9. **Approval versions:** Additive migration `0017_message_revisions.sql` adds immutable revision approvals and versioned message overlays. A single D1 batch approves the selected set atomically. Database triggers revalidate current delivery state and version; the send lease compares the selected revision version before claiming it. The Worker consumes the approved overlay. Tests inspect actual Gmail MIME built by the Worker with a mocked provider.
10. **Missing-document warning:** Final import review lists affected professors. Approval preview detects missing initial attachments, including mixed selections and follow-up-only attachments. The confirmation lists affected addresses and offers Attach Documents or Continue Without Attachments.
11. **Explicit attachment-free consent:** Continue Without Attachments stays disabled until its acknowledgment checkbox is selected. The server independently rejects approval without acknowledgment. New-campaign approval selection and audit records retain the decision; revision approval records retain equivalent consent.
12. **Timezone handling:** Existing UTC timestamps and IANA zones remain unchanged. Explicit local-time edits use the shared timezone converter with ambiguous daylight-saving times rejected. Existing Asia/Seoul and Asia/Karachi regression coverage passes. Conditional follow-up rules remain conditional on confirmed prerequisite delivery and no reply.
13. **D1 optimization:** The NULL-to-NULL follow-up schedule update fix is unchanged. Offline production-snapshot replay measured zero matched writes per idle schedule execution. An isolated revision fixture measured: opening 0, preview 0, approval 3, stale retry 0, nine idle sending phases 0, one active mocked send 11 matched row writes. These SQLite counts exclude D1 index amplification. Read-only account-wide telemetry reported no write warning; its hourly aggregates cannot isolate this release.
14. **Existing production state:** Pre/post encrypted snapshot comparison verified unchanged immutable records, original schedules/timezones, follow-up definitions, attachment associations, Gmail connection identities/scopes, Cron and Worker bindings. No message status transitions occurred during the comparison window. Counts remained: 14 campaign approvals, 108 message authorizations, 15 pending initial emails, 179 unqueued uncancelled follow-up steps, 140 message attachment associations, 111 document pins, 3 connections and 68 receipts. The post-release revision tables were empty: no live campaign was edited for testing. Normal OAuth token refresh remains enabled.
15. **Validation:** All 506 automated tests passed. Workspace typechecks, frontend production build and Worker build passed. Desktop (1440px) and mobile (390px) checks passed against both local builds and published frontend assets. Browser actions used an in-memory Worker; external browser requests were blocked. Published health returned 200, unauthenticated private state returned 401 with no-store, templates were accessible and CSP remained present. All 995 existing Worker functions were compared with production; only duplicate history, Gmail approval, route handling, sequence generation and send processing changed.
16. **Deployment:** The restore-tested additive migration was applied before deploying the byte-verified Worker artifact. Existing environment bindings and the one-minute Cron were preserved. The curated frontend upload excluded backups, credentials and diagnostics. The existing production alias points to the READY Vercel deployment. No paid infrastructure was introduced, Gmail OAuth was not reset, Cron was not manually triggered and no real test email was sent.
17. **Restrictions:** Emails due within two minutes, claimed/in flight, previously attempted, uncertain, sent, cancelled or protected by reply/suppression are locked. A revision approval covers at most 25 selected messages; additional eligible messages require another reviewed approval. Legacy follow-ups outside the sequence system remain read-only. Existing document/type/size limits and the 60-day horizon still apply. Upload a new document through Documents before selecting it in the editor. Closing the editor discards its unsaved revision form. Workspace deletion retains disclosed approval/contact/sending audit; explicit full account erasure remains tested and functional.
